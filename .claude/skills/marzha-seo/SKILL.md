# Поиск: замеренный спрос против опубликованного

## Закон

**Ни одного утверждения о поиске без команды, которая его показала.**

«Страница плохо оптимизирована», «нас не индексируют», «этот запрос
перспективный» — не находки. Находка называет команду и её вывод:

```bash
python3 tools/check_seo.py        # спрос против опубликованного
python3 tools/link_audit.py       # граф внутренних связей: сироты, тупики
python3 tools/metrika_report.py   # числа сайта (нужен METRIKA_TOKEN)
```

Правило то же, что у `site-auditor`: впечатление без замера — не находка.
Здесь оно распространено на поиск, где соблазн судить на глаз выше всего.

## Режимы

Режим задаётся первым словом после вызова. Без него берётся самый узкий,
подходящий под просьбу.

| Режим | Что делает | Чем меряется |
|---|---|---|
| `audit` | разбор по зависимостям сверху вниз | `check_seo.py`, `link_audit.py` |
| `map` | карта запрос → страница с решением по каждому | `keyword_map.py` |
| `content-gap` | кластеры без страницы и страницы без кластера | вывод `РЕШЕНИЕ` из `check_seo.py` |
| `page <путь>` | одна страница по всем ступеням | те же команды, срез по файлу |
| `internal-links` | сироты, тупики, асимметричные пары | `link_audit.py` |
| `geo` | видимость в ИИ-поиске | см. «Что закрыто из облачной сессии» |
| `plan` | порядок работ из находок | — |
| `implement` | правки, и только явно разрешённые | исполнитель `marzha-seo-implementer` |
| `verify` | независимая проверка после правок | исполнитель `marzha-seo-verifier` |

`audit`, `map`, `content-gap`, `page`, `internal-links`, `geo` ничего не
меняют. Правка в режиме разбора — нарушение, а не инициатива.

## Порядок разбора: по зависимостям, а не по удобству

Разбирать в этом порядке и не перепрыгивать. Правка на нижней ступени
бесполезна, пока сломана верхняя: заголовок страницы не имеет значения,
если страницы нет в карте сайта, а карта не имеет значения, если canonical
уводит с этой страницы.

1. **Доступность.** `robots.txt` не закрывает раздел.
2. **Обнаружение.** Страница в `sitemap.xml`; в карте нет адресов без
   страниц.
3. **Индексируемость.** Canonical указывает на саму страницу — либо
   осознанно на другую, и тогда страницы нет в карте. Два сигнала говорят
   одно.
4. **Неконкурентность.** Ни один `<title>` не повторяется; ни один целевой
   URL не собирает запросы из разных кластеров.
5. **Смысл.** Страница отвечает на отличимый запрос, а `<title>` и `<h1>`
   его несут — не пересказ темы.
6. **Связность.** У страницы есть входящие ссылки — `tools/link_audit.py`.
7. **Разметка.** Schema.org точна и не обещает того, чего на странице нет.
8. **Измерение.** Что изменилось после правки и когда это станет видно.

Ступени 1–4 закрыты командой `check_seo.py`, ступень 6 — `link_audit.py`.
Ступени 5, 7 и 8 — суждение, и они идут последними. Переписывание
заголовков до того, как сняты ступени 1–4, — самый частый способ потратить
заход впустую.

## Три исхода, а не два

У каждой находки называется, чем она подкреплена. Классы утверждений
заданы в `00_Core/Constitution.md` репозитория ai-business-os; для поиска
из них следует три исхода, и третий обязателен:

- **наблюдение** — вывод команды, который можно перезапустить;
- **вывод** — следствие из наблюдений, названное следствием;
- **нет доказательства** — проверить нечем, и это записывается так.

Третий исход — не поражение и не повод промолчать. Молчание о нём
превращает пробел в утверждение: читатель достраивает «раз не сказано —
значит проверено».

Сила находки и уверенность в ней разделяются. «Влияет сильно, уверенность
низкая» — законное сочетание; склеивать их в один балл нельзя.

## Чего не утверждаем никогда

Частотность, позиция, сложность запроса, CTR, конверсия, трафик
конкурентов и число ссылок не берутся из головы, из общего знания и из
ответа модели. Либо строка замера с датой и источником —
`content/strategy/semantic-core.csv` несёт колонки «Частотность»,
«Период», «Источник» именно для этого, — либо «нет доказательства».

Это прямое продолжение решения **«Цифры только из материала»**
(`CLAUDE.md`): придуманное число в SEO-отчёте стоит ровно столько же,
сколько придуманная сумма в заголовке статьи.

Отдельно не утверждается никогда:

- что правка приведёт к индексации, позиции, сниппету или упоминанию в
  ИИ-поиске — ни одна не приводит гарантированно;
- что длина `<title>`, число слов или плотность запроса сами по себе
  что-то решают;
- что валидная разметка Schema.org означает расширенный сниппет;
- что просадка вызвана обновлением алгоритма — по совпадению дат этого
  не устанавливают;
- «поисковик предпочитает…» без первоисточника или собственного замера.

Единого балла сайта — «SEO 73 из 100» — не бывает. Он склеивает
несравнимое и прячет, чего мы не знаем.

## Формат находки

Для каждой находки уровня «критично» и «высоко»:

```
Что            — в одну строку
Где            — URL или путь к файлу
Уровень        — критично / высоко / средне / низко
Исход          — наблюдение / вывод / нет доказательства
Уверенность    — высокая / средняя / низкая
Чем показано   — команда и её вывод
Чем это стоит  — на что влияет в деньгах или в пути посетителя
Что сделать    — конкретная правка, а не направление
Чем проверить  — команда, которая после правки должна замолчать
Что мешает     — блокер или зависимость, если есть
```

Уровни назначаются так:

- **критично** — ломает обход, индексируемость или целостность canonical;
- **высоко** — каннибализация, расхождение смысла страницы с запросом,
  разорванная архитектура, ошибка разметки на всём шаблоне, отсутствие
  страницы под подтверждённый денежный кластер;
- **средне** — заметное улучшение в ограниченном объёме;
- **низко** — шлифовка и слабо подтверждённое.

Внутри одного уровня раньше идёт то, что ближе к деньгам:
`references/business-context.md`.

## Четыре стадии результата, которые не смешиваются

Между «сделано» и «работает» три перехода, и каждый занимает своё время:

**сделано в репозитории** → **выложено на сайт** → **обработано
поисковиком** → **виден результат**.

Отчёт называет достигнутую стадию. «Исправили canonical» — первая
стадия, а не четвёртая, и до четвёртой из облачной сессии не дотянуться
вовсе. Смешение этих стадий — самый дешёвый способ отчитаться об успехе,
которого нет.

Следствия жёсткие: **живой сайт из облачной сессии не обходится,
консоли вебмастера не читаются, скорость не замеряется, видимость в
ИИ-поиске не проверяется.** Всё, что делается здесь, делается по файлам
репозитория. Утверждение «проверил страницу на сайте» из облачной сессии —
ложь, а не оговорка.

Что требует живого сайта или консоли — уходит на машину владельца или в
`.github/workflows/`, где ключ лежит секретом. Числа сайта берутся
прогоном `.github/workflows/metrika.yml`, ряд снимков — `content/metrics/`.

Режим `geo` из облака поэтому даёт только то, что видно по файлам: доступ
ботов в `robots.txt`, полноту разметки, наличие ответа на вопрос прямо в
тексте. Проверка «цитируют ли нас» — руками владельца, пятью запросами,
как записано в `docs/Skills_Import.md` репозитория ai-business-os.

## Карта запрос → страница

Механическая часть строится командой, образец колонок —
`templates/keyword-map.csv`:

```bash
python3 tools/keyword_map.py --out content/strategy/keyword-map.csv
```

Она группирует запросы по (кластер, подкластер, интент), назначает носителем
самый частотный и ставит предварительное решение. **Группировка — гипотеза,
а не вердикт**: два запроса одного подкластера могут оказаться разными
намерениями, и тогда `merge` неверен. Проверяет это `marzha-seo-strategist`,
а не команда.

Решение по каждой строке — одно из пяти, и **`no-page` равноправно
остальным**:

| Решение | Когда |
|---|---|
| `keep` | страница есть и отвечает запросу |
| `improve` | страница есть, но отвечает не на этот запрос |
| `merge` | две страницы делят один интент — оставить сильную |
| `create` | интент отличим и у страницы будет свой материал |
| `no-page` | лексический вариант уже закрытого интента |

Пять формулировок одной боли — «генподрядчик не платит», «задерживает
оплату», «не оплачивает работы», «не получили оплату», «как получить
деньги» — это одна страница, а не пять. Страница, пересказывающая
соседнюю ради вхождения, отнимает вес у соседней и не приводит никого.

Где живёт раздел и сколько страниц в нём будет — **решение владельца**
(Р-006 в ai-business-os: необратимое и задающее норму). Скил доводит до
решения замер и варианты, а не заводит раздел сам.

## Исполнители

| Работа | Кому |
|---|---|
| Технический разбор, ничего не меняя | `marzha-seo-auditor` |
| Интент, кластеры, карта запрос → страница | `marzha-seo-strategist` |
| Разрешённые правки | `marzha-seo-implementer` |
| Независимая проверка после правок | `marzha-seo-verifier` |

Проверяющий не может быть автором проверяемого: `implementer` не
подтверждает свою же работу, это делает `verifier`. Для разбора без правок
`implementer` не запускается вовсе.

Проверка возвращает по каждой задаче один из четырёх статусов:
`исправлено`, `исправлено частично`, `не исправлено`, `проверить нечем`.
**Изменённый файл сам по себе не доказательство**: доказательство — команда,
которая раньше показывала дефект, а теперь молчит.

## Таблица оправданий

| Звучит так | Что на самом деле |
|---|---|
| «Тут и так очевидно, что надо переписать title» | Ступень 5 разбирается после 1–4. Если страницы нет в карте, title не при чём |
| «Примерно тысяча показов в месяц» | Нет строки замера — значит «нет доказательства», а не «примерно» |
| «Сделал, теперь трафик вырастет» | Первая стадия из четырёх. Назвать достигнутую |
| «Проверил, на сайте всё в порядке» | Из облачной сессии сайт закрыт (403). Проверено по файлам — так и сказать |
| «Заведём сразу сто страниц под кластер» | Состав каталога — решение владельца, а тонкие страницы отнимают вес у сильных |
| «`check_seo.py` показывает РЕШЕНИЕ, значит всё хорошо» | Это не «хорошо», это «ждёт владельца». Довести до вопроса с вариантами |
| «Файл поправлен, значит дефект закрыт» | Доказательство — замолчавшая команда, а не изменённый файл |

## Признаки, что правило обошли

- В отчёте есть число без источника и даты.
- Сказано «проверил» — и не названа команда.
- Правки заголовков сделаны на страницах, которых нет в `sitemap.xml`.
- «Нет доказательства» не встречается ни разу: значит, пробелы
  дописаны догадкой.
- Строка `РЕШЕНИЕ` из `check_seo.py` исправлена молча — архитектура
  изменена без владельца.
- В карте запрос → страница нет ни одного `no-page`.
