# Instagram и MAX

У обеих площадок нет API, пригодного для автопубликации в этом проекте:
Instagram Graph API требует бизнес-аккаунт и приложение Meta, у MAX
возможности для каналов ограничены. Поэтому навык готовит материал «на одну
кнопку» — человек копирует и публикует сам.

Файл: `content/social/<slug>.md`. На сайт он не попадает — папка `content`
исключена из деплоя.

## Шаблон файла

```markdown
# <Заголовок материала>

Ссылка с метками: https://marzhavbetone.ru/articles/<slug>.html?utm_source=instagram&utm_medium=carousel&utm_campaign=<slug>

## Instagram: карусель

### Карточка 1 — обложка
<Крючок в 4–7 словах. Тот же тезис, что в заголовке статьи.>

### Карточка 2
<Ситуация: что происходит на объекте.>

### Карточка 3
<Механика: почему это работает против подрядчика.>

### Карточки 4–7
<По одному проверяемому пункту на карточку. Один тезис — одна карточка.>

### Карточка 8 — действие
<Что сделать сегодня + «ссылка в описании профиля».>

## Instagram: подпись к публикации

<2–4 абзаца по существу. В конце — призыв и напоминание про ссылку в профиле:
кликабельных ссылок в подписи нет.>

<Хештеги: 5–8 по теме, без мусорных высокочастотных.>

## MAX: пост

Ссылка с метками: https://marzhavbetone.ru/articles/<slug>.html?utm_source=max&utm_medium=post&utm_campaign=<slug>

<Текст поста. Формат ближе к Telegram: ситуация, 2–4 пункта, переход к
разбору. Разметку не используем — переносим как обычный текст.>
```

## Правила

- **Один тезис на карточку.** Карусель, где на карточке три мысли, не читается
  с телефона.
- **UTM обязательны и различаются по площадке.** `utm_source=instagram` и
  `utm_source=max` — иначе продажи из разных мест сольются в один поток и
  станет непонятно, что работает.
- **В подписи Instagram ссылки не кликабельны.** Поэтому в тексте — «ссылка в
  описании профиля», а сама ссылка с метками ставится в bio или в Stories.
- **Обложку карусели** можно взять ту же, что у статьи: `assets/<slug>.png`.
  Формат 1200×630 подходит и для ленты, хотя вертикальный 1080×1350 занимает
  больше экрана — если человек попросит вертикальные карточки, генерируй их
  отдельно.
- **Цифры и суммы — только те, что есть в статье.** Карточка с выдуманной
  суммой разойдётся по пересылкам, и опровергать её будет поздно.

## Картинки карточек

Текст карточек хранится в `content/social/<slug>.md`, картинки не хранятся:
они полностью выводятся из текста и собираются генератором.

```bash
python3 tools/build_cards.py <slug>
```

На выходе — PNG 1080×1350 в `content/social/cards/<slug>/`, по одному файлу
на карточку, в том же стиле, что обложки статей: графитовый фон, оранжевая
полоса слева, номер карточки сверху, адрес сайта снизу. Кегль подбирается
автоматически под длину текста; если текст не помещается даже минимальным,
скрипт возвращает 1 и называет номера карточек — их нужно сократить, а не
уменьшать шрифт дальше.

Без Python под рукой то же самое делает workflow **Build carousel cards**:
Actions → Build carousel cards → Run workflow → ввести slug. Картинки
приезжают архивом в артефактах запуска.
