# Посты для Telegram-канала

Каждый пост — отдельный файл `*.md` в этой папке. Публикацией занимается
`tools/post_telegram.py`, который запускается по расписанию из
`.github/workflows/telegram.yml`.

## Формат файла

```
---
publish_at: 2026-07-28 10:00
link: https://marzhavbetone.ru/articles/nekotoraya-statya.html
utm_campaign: article-nekotoraya-statya
preview: true
---
<b>Заголовок поста</b>

Основной текст. Ссылка подставится на место {link} — уже с UTM-метками.
```

| Поле | Обязательно | Смысл |
|---|---|---|
| `publish_at` | да | Когда публиковать, московское время, формат `ГГГГ-ММ-ДД ЧЧ:ММ` |
| `link` | нет | Ссылка на сайт; к ней сами добавятся UTM-метки |
| `utm_campaign` | нет | Метка кампании; по умолчанию — имя файла |
| `preview` | нет | `false` — не показывать превью ссылки |

## Правила

- **Разметка:** только теги, которые понимает Telegram — `<b>`, `<i>`, `<u>`,
  `<s>`, `<a>`, `<code>`, `<pre>`, `<blockquote>`, `<span>`, `<tg-spoiler>`.
  Любой другой тег остановит публикацию с понятной ошибкой.
- **Длина:** не больше 4096 символов.
- **Повторов не бывает:** опубликованные посты записываются в
  `published.json`. Удалять оттуда записи вручную не нужно — иначе пост
  уйдёт в канал второй раз.
- **Изменить текст уже опубликованного поста нельзя** — публикация
  односторонняя. Правьте пост до наступления `publish_at`.

## Проверка перед публикацией

Проверить токен, доступ к каналу и право публикации:

```bash
TELEGRAM_BOT_TOKEN=... python3 tools/post_telegram.py --check
```

Отвечает на три вопроса, из-за которых обычно не работает публикация: верен
ли токен, видит ли бот канал, есть ли право отправки сообщений. Эта же
проверка выполняется в workflow перед каждой публикацией.

Посмотреть, что и когда уйдёт (разметка и длина тоже проверяются):

```bash
python3 tools/post_telegram.py --dry-run
```

Ничего не отправит.

То же можно сделать в GitHub: Actions → «Post to Telegram» → Run workflow
с включённой галочкой пробного прогона.
