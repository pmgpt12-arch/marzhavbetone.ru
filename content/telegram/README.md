# Посты для Telegram-канала

Каждый пост — отдельный файл `*.md` в этой папке. Публикацией занимается
`tools/post_telegram.py`, который запускается по расписанию из
`.github/workflows/telegram.yml`.

## Формат файла

```
---
publish_at: 2026-07-28 10:00
link: https://marzhavbetone.ru/articles/nekotoraya-statya.html
utm_campaign: article-nekotoraya-statya
preview: true
---
<b>Заголовок поста</b>

Основной текст. Ссылка подставится на место {link} — уже с UTM-метками.
```

| Поле | Обязательно | Смысл |
|---|---|---|
| `publish_at` | да | Когда публиковать, московское время, формат `ГГГГ-ММ-ДД ЧЧ:ММ` |
| `link` | нет | Ссылка на сайт; к ней сами добавятся UTM-метки |
| `utm_campaign` | нет | Метка кампании; по умолчанию — имя файла |
| `utm_content` | нет | Вариант ссылки, когда на одну тему их несколько |
| `preview` | нет | `false` — не показывать превью ссылки |

## Разметка перехода

Отправка сама собирает
`utm_source=telegram&utm_medium=post&utm_campaign=<из шапки>` — в тексте
поста метки нет по устройству. Стандарт закреплён в
`data/content/rules.yaml` и не меняется здесь: сообщения 46–52 ушли с
`medium=post`, и другой `medium` разорвал бы ряд отчётности пополам.

`utm_content` нужен не всегда: `utm_campaign` уже различает пост от поста.
Он ставится, когда на одну тему уходит несколько ссылок — анонс и повтор,
посев, размещение, — иначе они сольются в один столбец отчёта.

Первый замер живыми данными, 16.08.2026 (прогон `metrika.yml` на 30 дней,
период 17.07 — 15.08, снимок в коммите `b86a584`):

| Канал | Визитов | product_opened | checkout_open | purchase |
|---|---|---|---|---|
| dzen | 27 | 0 | 0 | 0 |
| telegram | 1 | 0 | 0 | 0 |
| без метки | 80 | — | — | — |

Всего 108 визитов, с меткой 28. Единственный визит из Телеграма пришёл по
кампании `stroitelnaya-smeta` (пост 49 от 06.08). За недельное окно
09 — 15.08 визитов с меткой нет вовсе, хотя в него попали три поста.

Читается это так: канал в состоянии LIVE, но не в состоянии
CONVERTING — и даже не в состоянии «приводит трафик». Дзен при семи
публикациях дал в 27 раз больше переходов, чем Телеграм при семи. Причина
замером не установлена: числа говорят, что переходов нет, и не говорят
почему.

Разрез собирает `tools/metrika_report.py`, ключ `utm` в снимке; проверка
разбора — `tools/test_metrika_utm.py`. Повторить:
«Actions → Metrika snapshot → Run workflow», дни и запись — параметрами.

Цепочка от перехода до заказа проверена сквозным прогоном 16.08.2026
(браузер, локальный сервер, покупка не совершалась): метки принимает
`attribution.js`, первое касание переживает переходы по сайту, `app.js`
кладёт его в заказ, `payment.php` пишет `source`, `medium`, `campaign`,
`content`, `landing`, а `success.html` называет канал в параметрах цели
`purchase`. Разметку самой ссылки держит `tools/test_post_telegram.py` в
гейте.

## Правила

- **Разметка:** только теги, которые понимает Telegram — `<b>`, `<i>`, `<u>`,
  `<s>`, `<a>`, `<code>`, `<pre>`, `<blockquote>`, `<span>`, `<tg-spoiler>`.
  Любой другой тег остановит публикацию с понятной ошибкой.
- **Длина:** не больше 4096 символов.
- **Повторов не бывает:** опубликованные посты записываются в
  `published.json`. Удалять оттуда записи вручную не нужно — иначе пост
  уйдёт в канал второй раз.
- **Изменить текст уже опубликованного поста нельзя** — публикация
  односторонняя. Правьте пост до наступления `publish_at`.
- **Ссылка на Дзен — последней строкой, после `{link}`.** Пока в Дзене нет
  10 подписчиков, автотрансляция из `rss.xml` не включается, а подписчиков
  даёт перелив из Telegram. Выше основной ссылки её ставить не нужно:
  превью Telegram строит по первой ссылке в сообщении, а вести читателя мы
  хотим на сайт.

  ```
  Разборы в длинном формате — в <a href="https://dzen.ru/marzhavbetone">Дзене</a>.
  ```

## Проверка перед публикацией

Проверить токен, доступ к каналу и право публикации:

```bash
TELEGRAM_BOT_TOKEN=... python3 tools/post_telegram.py --check
```

Отвечает на три вопроса, из-за которых обычно не работает публикация: верен
ли токен, видит ли бот канал, есть ли право отправки сообщений. Эта же
проверка выполняется в workflow перед каждой публикацией.

Посмотреть, что и когда уйдёт (разметка и длина тоже проверяются):

```bash
python3 tools/post_telegram.py --dry-run
```

Ничего не отправит.

То же можно сделать в GitHub: Actions → «Post to Telegram» → Run workflow
с включённой галочкой пробного прогона.
