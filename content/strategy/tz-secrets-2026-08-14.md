# ТЗ: инструкция по добавлению секретов доступа к данным

Задание для отдельной сессии. Дата: 14.08.2026.

## Что сделать

Написать `docs/SECRETS.md` — инструкцию владельцу, как получить и
добавить три секрета в GitHub Secrets репозитория
`pmgpt12-arch/marzhavbetone.ru`.

Инструкция для человека, а не для агента: владелец выполняет её руками,
потому что выдача ключа — необратимое действие наружу и остаётся за ним
(Р-006). Всё, что вокруг, уже автоматизировано.

## Состояние, проверенное командой

Не верить этому разделу на слово — перемерить. Задание говорит, что
делать; состояние сессия меряет сама.

| факт | чем проверено |
|---|---|
| ни одного секрета нет | прогон `search-demand.yml` на main, лог шага «Проверить доступ»: `WM: секрета нет`, `MT: секрета нет` |
| снимков Метрики нет | `ls content/metrics/` → только `seo-live-audit-*.md` |
| счётчик стоит и собирает | `grep -c 'METRIKA_ID = ' attribution.js` → 1, id 111149105; `grep -rl attribution.js --include=*.html . \| grep -v ^./content \| wc -l` → 80 |
| целей в коде 13 | `grep -rn 'mvbTrackGoal\|reachGoal' --include=*.js .` |

## Три секрета

| имя | для чего | кто ждёт |
|---|---|---|
| `METRIKA_TOKEN` | выгрузка чисел Метрики, объявление целей | `tools/metrika_report.py`, `.github/workflows/metrika.yml` |
| `YANDEX_WEBMASTER_TOKEN` | показы, клики, позиции по запросам | `tools/search_demand.py`, `.github/workflows/search-demand.yml` |
| ключи Search Console | то же по Google | **сборщика нет** — назвать это прямо, не обещать |

Право для Вебмастера — `webmaster:hostinfo`. Для Метрики достаточно
чтения статистики плюс права на изменение счётчика (цели заводятся
прогоном `--create-goals`).

## Что должно быть в инструкции по каждому секрету

1. Что это за ключ и какой службы.
2. Где получить — точный путь в интерфейсе, а не «в настройках».
3. Какое право запросить и почему именно оно.
4. Куда положить: Settings → Secrets and variables → Actions → New
   repository secret, точное имя секрета.
5. **Как проверить, что заработало** — командой, а не ощущением:
   - Вебмастер: запустить `search-demand.yml` с `probe: true`, в логе
     ожидается `Доступ есть: user_id=…, host_id=…`; отказ печатается с
     кодом — 401 токен не той службы, 403 нет права `webmaster:hostinfo`;
   - Метрика: запустить `metrika.yml`, ожидается снимок в
     `content/metrics/`, а не строка «сбор НЕ ЗАПУСКАЛСЯ».
6. Что перестаёт быть сломанным после добавления — одной строкой.

## Запреты

- Значение токена не попадает ни в репозиторий, ни в переписку, ни в лог.
  В инструкции не должно быть места, где токен просят прислать в чат.
- Не писать «примерно так выглядит токен» и не приводить образцов.
- Не утверждать, что сборщик Search Console существует.
- Порядок шагов не выдумывать: если точный путь в интерфейсе неизвестен —
  проверить в документации службы и сослаться на неё, а не описать по
  памяти.

## Приёмка

Инструкция принята, когда по ней проходит человек, у которого нет
контекста проекта, и на каждом шаге получает проверяемый результат.
Финальная проверка одна: прогон `search-demand.yml` с `probe: true`
завершается кодом 0 и печатает `Доступ есть`.
