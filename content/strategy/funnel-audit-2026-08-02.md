Пять проверок из определения исполнителя `site-auditor`, прогнанные
командой на `main` в состоянии после слияния PR #95.

## 1. Статья без выхода на товар — 0 из 28

Чисто. В каждой из двадцати восьми статей есть хотя бы одна ссылка на
`products/`. Путь из поиска нигде не обрывается на тексте.

## 2. Статья без лид-магнита — было 21 из 28, стало 13

Утром блок бесплатного материала стоял в семи статьях — тех, на которые
ведут семь дней калибровки Дзена. Остальные двадцать одна выхода на
бесплатный материал не имели: читатель, не готовый платить, уходил без
следа, и адрес мы у него не брали.

Добавлено восемь связок — только те, где материал действительно
относится к теме статьи:

| Статья | Материал |
|---|---|
| `podpisannaya-ks2-ne-znachit-chto-zaplatyat` | КС подписаны, денег нет |
| `pyat-dokazatelstv-vypolneniya` | КС подписаны, денег нет |
| `raboty-ne-prinyaty` | КС без возврата |
| `akt-osvidetelstvovaniya-skrytyh-rabot` | КС без возврата |
| `ispolnitelnaya-dokumentaciya-sostav` | КС без возврата |
| `dopraboty-bez-soglasheniya` | Допработы |
| `vsyo-vklyucheno-v-cenu` | Допработы |
| `stroitelnyy-musor-v-smete` | Допработы |

**Тринадцать статей остаются без блока намеренно.** Под их темы
бесплатного материала не существует:

- удержания — четыре статьи (`garantiynoe-uderzhanie-chto-eto`,
  `srok-garantiynogo-uderzhaniya`, `vozvrat-garantiynogo-uderzhaniya`,
  плюс `skidka-15-procentov`);
- договор — две (`dogovor-subpodryada-obrazec`,
  `protokol-raznoglasiy-k-dogovoru`);
- банкротство — четыре (`bankrotstvo-genpodryadchika-5-markerov`,
  `srok-vklyucheniya-v-reestr`, `zayavlenie-o-vklyuchenii`,
  `zapros-arbitrazhnomu-upravlyayushchemu`);
- аванс — две (`avans-eto-ne-dengi-eto-kryuchok`,
  `bankovskaya-garantiya-na-vozvrat-avansa`);
- разбор без своей темы — одна (`genpodryadchik-zarabatyvaet-na-vas`).

Ставить туда ближайший по смыслу материал значило бы повторить ошибку,
из-за которой сегодня уже переписывали четыре текста: блок обещал то,
чего в наборе нет. **Это не недоделка проверки, а измеренный пробел в
продукте: нужен четвёртый и пятый бесплатный материал — по удержаниям и
по договору.** Оба кластера измерены и оба имеют платный комплект, то
есть материал есть из чего собрать.

## 3. Страница магнита со старым счётчиком — дефект не воспроизвёлся

В задании сказано, что страницы `materialy/*` остались на `?v=2`, тогда
как остальные на `?v=3`, и из кэша приходит файл с выключенным
счётчиком.

По файлам это не так, и дважды:

- Версии одинаковы на всех страницах: `app-script.php?v=20` и
  `attribution.js?v=1` — включая три страницы магнитов. Других
  версионированных ассетов нет.
- `app-script.php` отдаёт заголовки `no-cache, no-store,
  must-revalidate`. Для него параметр `?v=` не работает вовсе: файл не
  кэшируется по определению, и рассинхрон версий на него не влиял бы.

Правка не требуется. Записано, чтобы следующая сессия не искала этот
дефект заново.

## 4. Заголовок против измеренной фразы — 8 из 28

Заголовок или `<h1>` содержит измеренную фразу у восьми статей:

| Частота | Статья | Фраза |
|---:|---|---|
| 26 177 | четыре статьи кластера реестра | «реестр требований кредиторов» |
| 2 284 | `neotrabotannyy-avans` | «неотработанный аванс» |
| 323 | `bankovskaya-garantiya-na-vozvrat-avansa` | «банковская гарантия на возврат аванса» |
| 283 | `vozvrat-avansa-po-dogovoru-podryada` | «возврат аванса по договору подряда» |
| 23 | `bankrotstvo-genpodryadchika-5-markerov` | «банкротство генподрядчика» |

У двадцати совпадения нет. Само по себе это не дефект: восемь статей
делались под замер, двадцать писались раньше него, под боль, а не под
фразу. Но это объясняет, почему поиск их не находит, и подтверждает
вывод `content/strategy/README.md`: спрос лежит не там, где боль, а там,
где бланк.

Заголовки задним числом не переписываются: часть адресов уже отправлена
на переобход, а смена заголовка обнуляет накопленное. Правильный ход —
новые страницы под измеренные фразы, а не правка старых.

## Что осталось незакрытым

**Счётчик Метрики не установлен.** Это не проверка, а задача 2 задания, и
она упирается в номер счётчика, которого у меня нет. Уточнение по
формулировке задания: `app.js` вызывает `reachGoal` **под условием** —
`if (typeof window.ym === 'function' && window.METRIKA_ID)`. Цели не
«уходят в пустоту», а не срабатывают вовсе. Практический итог тот же —
измерения нет, — но сломанного кода на сайте нет тоже: не хватает только
счётчика и номера.
