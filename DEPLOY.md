# Автодеплой из GitHub на хостинг reg.ru

Настраивается один раз. После этого любой коммит в ветку `main`
автоматически выкладывается на сайт: GitHub подключается к хостингу по
SSH и обновляет файлы. Ручная заливка через FTP больше не нужна.

## Ваши данные

| Параметр | Значение |
|---|---|
| Сервер | `server116.hosting.reg.ru` |
| SSH-пользователь | `u3581543` |
| Домашняя папка | `/var/www/u3581543/data` |
| Папка сайта | `~/www/marzhavbetone.ru` |
| Папка продуктов | `~/products-marzhavbetone` (вне webroot) |

---

## Шаг 1. Включить SSH-доступ на хостинге

1. Откройте личный кабинет **reg.ru** → карточка услуги хостинга.
2. Вкладка **«Доступы»**.
3. Найдите **SSH-доступ**. Если выключен — включите.
4. Запомните логин (`u3581543`) — он же используется для FTP.

Без этого шага деплой не подключится к серверу.

## Шаг 2. Создать ключ доступа (на своём ПК)

Ключ — это пара файлов: секретный останется в GitHub, публичный положим
на хостинг. Пароль от хостинга при этом нигде не хранится.

Откройте **PowerShell** (Пуск → наберите `PowerShell` → Enter) и выполните:

```powershell
cd $HOME
ssh-keygen -t ed25519 -f deploy_key
```

На вопрос `Enter passphrase` — нажмите **Enter**. На повторный вопрос —
снова **Enter** (пароль на ключ не нужен, GitHub не сможет его ввести).

Появятся два файла в `C:\Users\X6`:

- `deploy_key` — **секретный**, пойдёт в GitHub Secrets;
- `deploy_key.pub` — **публичный**, пойдёт на хостинг.

## Шаг 3. Положить публичный ключ на хостинг

1. Откройте публичный ключ:

   ```powershell
   notepad $HOME\deploy_key.pub
   ```

   В Блокноте одна длинная строка вида
   `ssh-ed25519 AAAAC3NzaC1... github-deploy`. Выделите всё (**Ctrl+A**),
   скопируйте (**Ctrl+C**).

2. Откройте **ISPmanager** (из кабинета reg.ru) → в левом меню
   **«Shell-клиент»**. Откроется терминал в браузере.

3. Введите команду, заменив текст в кавычках на скопированную строку:

   ```bash
   mkdir -p ~/.ssh && echo 'ssh-ed25519 AAAA...ваша_строка...' >> ~/.ssh/authorized_keys && chmod 700 ~/.ssh && chmod 600 ~/.ssh/authorized_keys
   ```

   Вставка в веб-терминал — правая кнопка мыши или **Ctrl+Shift+V**.

4. Проверьте с ПК (PowerShell):

   ```powershell
   ssh -i $HOME\deploy_key u3581543@server116.hosting.reg.ru "echo OK"
   ```

   На первый вопрос о подлинности хоста ответьте `yes`. Ответ `OK`
   **без запроса пароля** = ключ работает.

## Шаг 4. Добавить секреты в GitHub

Репозиторий `marzhavbetone.ru` → **Settings** → **Secrets and variables**
→ **Actions** → кнопка **New repository secret**. Добавьте три штуки:

| Name | Secret |
|---|---|
| `DEPLOY_HOST` | `server116.hosting.reg.ru` |
| `DEPLOY_USER` | `u3581543` |
| `DEPLOY_SSH_KEY` | Всё содержимое файла `deploy_key` (`notepad $HOME\deploy_key`, Ctrl+A, Ctrl+C) — от строки `-----BEGIN OPENSSH PRIVATE KEY-----` до `-----END OPENSSH PRIVATE KEY-----` включительно |

Необязательные секреты (нужны, только если пути или порт отличаются):

| Name | Когда нужен | По умолчанию |
|---|---|---|
| `DEPLOY_PORT` | SSH не на 22 порту | `22` |
| `DEPLOY_PATH` | другая папка сайта | `www/marzhavbetone.ru` |
| `DEPLOY_PRODUCTS_PATH` | другая папка продуктов | `products-marzhavbetone` |

После добавления секретов удалите ключи с ПК — они больше не нужны:

```powershell
del $HOME\deploy_key; del $HOME\deploy_key.pub
```

## Шаг 5. Указать сайту, где лежат файлы продуктов

ISPmanager → **Менеджер файлов** → `www` → `marzhavbetone.ru` →
файл `config.php` → **Изменить**. Добавьте в конец строку:

```php
define('PRODUCTS_DIR', '/var/www/u3581543/data/products-marzhavbetone');
```

Сохраните. Этот файл деплой никогда не перезаписывает — боевые ключи
ЮКассы остаются только на сервере.

## Шаг 6. Пробный прогон

Первый запуск лучше сделать вхолостую — он покажет, что изменится, но
ничего не тронет.

1. GitHub → репозиторий → вкладка **Actions**.
2. Слева выберите **«Deploy to server»**.
3. Справа **Run workflow** → включите галочку
   **«Пробный прогон»** → **Run workflow**.
4. Откройте запуск и просмотрите лог. В шаге «Preflight checks» должно
   быть: SSH-подключение ок, папка сайта ок, папка продуктов ок.

Если всё зелёное — запустите ещё раз **без** галочки. Файлы уедут на
хостинг, последний шаг проверит, что сайт отвечает `HTTP 200`.

Дальше деплой запускается сам при каждом коммите в `main`.

## Что деплой делает и чего не делает

Заливает содержимое репозитория в папку сайта и `products-storage/` — в
закрытую папку продуктов. Устаревшие файлы на хостинге удаляются, чтобы
сайт точно совпадал с репозиторием.

**Никогда не трогает на хостинге:**

- `config.php` — боевые ключи ЮКассы;
- `orders/` — заказы покупателей и ссылки выдачи;
- `.well-known/` — подтверждение SSL-сертификата;
- всё за пределами папок сайта и продуктов.

**Защита от ошибки:** перед заливкой проверяется, что в целевой папке
есть `index.html`. Если путь задан неверно, деплой останавливается и
ничего не удаляет.

## Если что-то пошло не так

| Ошибка в логе | Причина | Решение |
|---|---|---|
| `Не удалось получить SSH-ключ хоста` | неверный `DEPLOY_HOST` или SSH выключен | проверьте секрет; включите SSH в кабинете reg.ru (Доступы) |
| `Не удалось подключиться по SSH как ...` | ключ не добавлен на хостинг или скопирован не полностью | повторите шаг 3, проверьте `ssh -i ... "echo OK"` с ПК |
| `На хостинге нет папки ...` | другой путь к сайту | посмотрите путь в Менеджере файлов, задайте секрет `DEPLOY_PATH` |
| `нет index.html — не похоже на корень сайта` | путь указывает не туда | проверьте `DEPLOY_PATH` |
| `Сайт ответил 500` | ошибка PHP после обновления | смотрите логи в ISPmanager → Журналы WWW-запросов |

Если на хостинге нет `rsync`, деплой автоматически переключается на
заливку по SFTP — отдельных действий не требуется.
