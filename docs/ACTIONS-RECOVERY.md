# Минуты GitHub Actions кончились: что сделано и что осталось владельцу

Замер 23.08.2026. Файл — разбор и порядок восстановления, а не план.

## Что именно сломалось

Задания не начинают выполняться: отказ за 2–3 секунды, **выполненных
шагов ноль**. Перезапуск даёт то же самое (попытка 2, `05:14:15 →
05:14:18`). Разом по трём разным процессам — `Проверки`, `Проверки
рендером`, `Deploy`. Всё, что запускалось до 04:47, проходило.

Локально тот же коммит проходит весь `checks.yml` целиком. Дефекта в коде
нет, и искать его не нужно.

Репозиторий **приватный** (`"private": true` в ответе API), значит минуты
метрируются: бесплатный предел личного аккаунта — 2000 минут в месяц.

Логи прогонов недоступны — `404` и на свежие, и на старые: у сессии нет
права их скачивать. Поэтому точная строка отказа здесь не приводится, а
вывод сделан по форме отказа и по тому, что он одинаков для всех
процессов.

## Куда уходили минуты, и это главное

**`telegram.yml` шёл ежечасно** — `cron: '5 * * * *'`, 24 прогона в сутки.
К 23.08 их накопилось **413**.

А публиковать было нечего: у **всех до одного** постов в
`content/telegram/` время публикации `10:00` МСК. Двадцать три прогона из
двадцати четырёх заканчивались строкой «к публикации сейчас: 0» — и каждый
оплачивался, потому что GitHub округляет любое задание вверх до полной
минуты.

Это исправлено в этом же заходе: два прогона в сутки вместо двадцати
четырёх, `5 7 * * *` и `5 15 * * *`. **Прогонов меньше примерно на 92%**,
и ни один пост не теряется: публикатор берёт всё, чему срок уже наступил
(`publish_at <= now`), а не только наступивший в этот час. Второй прогон
оставлен не для частоты, а на случай пропущенного расписания.

Точную экономию в минутах назвать нечем — страница оплаты сессии
недоступна. Названо то, что измеримо: число прогонов и правило округления.

## Что должен сделать владелец — один заход

Я работаю в облачном контейнере, а не на домашнем компьютере: поставить
runner на вашу Ubuntu из сессии невозможно физически. Это не отказ, а
граница среды.

Runner ставится **в домашний каталог, root не нужен**.

1. Открыть страницу с токеном (он одноразовый и живёт час):
   `https://github.com/pmgpt12-arch/marzhavbetone.ru/settings/actions/runners/new?arch=x64&os=linux`

2. Выполнить на домашней машине, подставив токен со страницы:

```bash
mkdir -p ~/actions-runner && cd ~/actions-runner
curl -o actions-runner-linux-x64.tar.gz -L \
  https://github.com/actions/runner/releases/latest/download/actions-runner-linux-x64.tar.gz
tar xzf actions-runner-linux-x64.tar.gz
./config.sh --url https://github.com/pmgpt12-arch/marzhavbetone.ru \
            --token СЮДА_ТОКЕН_СО_СТРАНИЦЫ \
            --labels self-hosted,linux,x64,home \
            --unattended --replace
sudo ./svc.sh install && sudo ./svc.sh start   # автозапуск; без него — ./run.sh
```

Шаг с `svc.sh` — единственный, где нужен `sudo`, и только чтобы runner
поднимался после перезагрузки. Без него всё работает, пока открыт
терминал с `./run.sh`.

3. Сказать сюда, что runner появился в списке — дальше перевод процессов
   и проверка делаются из сессии.

**Порядок перевода, когда runner будет:** сначала один безопасный процесс
(`checks.yml`) и проверка, что задание стартует, шаги идут и минуты
GitHub не тратятся. Выкладку переводить только после этого и не запускать
на бою ради проверки.

## Чего делать не нужно

Repository-scoped runner **не должен исполнять код недоверенных PR**:
репозиторий приватный, чужих форков нет, но правило остаётся — на
`pull_request_target` и на форки его не вешать.

Своего runner-оркестратора не пишем, Claude Dispatcher не трогаем.

## Если ждать

Минуты бесплатного предела обновляются в начале расчётного периода.
Дата — на странице оплаты, из сессии она не читается, поэтому «через
столько-то дней» здесь не пишется. Урезанный Телеграм снижает расход в
следующем периоде независимо от того, появится runner или нет.
