# Instagram: разовая настройка владельцем

Всё, что можно сделать без владельца, уже сделано: клиент Graph API
(`tools/instagram_publish.py`), прогон (`.github/workflows/instagram.yml`),
ролики и подписи. Не хватает ровно одного — доступа, который выдаётся
только из аккаунта.

Ниже минимальный набор шагов. Он делается один раз; дальше публикация идёт
кнопкой прогона.

## Почему это нельзя сделать из сессии

Замер 16.08.2026 из облачной сессии:

```
curl -sS -o /dev/null -w '%{http_code}' https://graph.facebook.com  → 000
curl -sS -o /dev/null -w '%{http_code}' https://www.instagram.com   → 000
```

Оба адреса закрыты прокси. У раннера GitHub выход свой, поэтому публикация
живёт в прогоне. Это не обход ограничения, а тот же порядок, что у отправки
в Телеграм и съёмки фрагментов.

## Что нужно от владельца

### 1. Тип аккаунта

Instagram-аккаунт проекта должен быть **профессиональным** — Business или
Creator. Личный аккаунт Graph API не публикует вовсе, и это ограничение
Meta, а не наше.

Инстаграм → Настройки → Тип аккаунта → переключить на профессиональный.

### 2. Связка со страницей Facebook

Профессиональный аккаунт должен быть связан со страницей Facebook. Страницу
можно завести пустую — она нужна как держатель прав доступа, вести её не
требуется.

### 3. Приложение Meta

developers.facebook.com → создать приложение типа Business → добавить
продукт **Instagram Graph API**.

Права, которые нужны приложению:

- `instagram_basic`
- `instagram_content_publish`
- `pages_read_engagement`
- `pages_show_list`

### 4. Долгоживущий токен

Короткий токен живёт час и для прогона бесполезен. Нужен долгоживущий
(60 дней) — обменивается в Graph API Explorer или запросом
`oauth/access_token` с `grant_type=fb_exchange_token`.

Токен придётся обновлять раз в два месяца. Прогон говорит срок годности
сам: режим `probe` печатает дату истечения, и пропустить её молча нельзя.

### 5. Номер аккаунта

`IG_USER_ID` — это идентификатор Instagram-аккаунта, не имя пользователя.
Берётся запросом к связанной странице:

```
GET /{page-id}?fields=instagram_business_account
```

### 6. Секреты в репозитории

GitHub → Settings → Secrets and variables → Actions → New repository secret:

| Имя | Что это |
| --- | --- |
| `IG_ACCESS_TOKEN` | долгоживущий токен из шага 4 |
| `IG_USER_ID` | номер аккаунта из шага 5 |

В репозиторий эти значения не кладутся ни в каком виде — ни в файл, ни в
переписку.

## Проверка, что всё сошлось

Actions → Instagram → Run workflow → `mode: probe`.

Прогон печатает имя аккаунта, число подписчиков и публикаций, срок
действия токена и выданные права. Ничего не публикует. Если в правах нет
`instagram_content_publish`, прогон отказывает с этой строкой — до
публикации, а не во время.

## Публикация

Actions → Instagram → Run workflow → `mode: publish`, и:

- `media_url` — **публичный** адрес файла. Graph API не принимает загрузку
  тела: Meta забирает файл сама, поэтому ролик сначала выкладывается на
  сайт, и сюда отдаётся его адрес. Приватная ссылка не годится.
- `media_kind` — `reel` или `image`.
- `caption_file` — путь к файлу подписи в репозитории.

Прогон дожидается сборки контейнера на стороне Meta (она асинхронная и
занимает десятки секунд), публикует и отдельным запросом читает
получившуюся запись — чтобы в журнале осталась не «запрос принят», а адрес
живой публикации.

## Чего здесь нет

Ответов в Direct, работы с комментариями и Stories. Комментарии ведутся
отдельным контуром (Р-043), Direct по решению владельца не используется
для продаж.
