## Контроль повторяемой ошибки

**Первопричина:** заголовки и свойства DOCX, PDF-колонтитулы, а также зафиксированный SHA архива в production builder обновляются независимо; неполная смена бренда приводит либо к появлению старого названия в товаре, либо к невозможности его скачать.

**Постоянное правило:** при смене бренда проверять DOCX XML (включая header/footer/core.xml), PDF видимый и извлечённый текст, XLSX XML, ZIP SHA всех файлов и production SHA-пиннинг; проводить реальную проверку `mvb_build_product_zip` после изменения. Превью генерировать только из точного вновь опубликованного архива.

**Технический долг:** результаты production зафиксированы, но основная ветка GitHub ещё не синхронизирована. Следующий массовый деплой из устаревшей ветки способен перезаписать утверждённую статью или восстановить старый SHA товара. До массовой публикации синхронизировать только нужные файлы с актуальной боевой версией; не запускать слепую заливку всего репозитория.
