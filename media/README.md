# Готовые ролики под публикацию

Каталог существует ради одного технического требования площадки.

**Почему бинарник лежит в репозитории.** Graph API не принимает загрузку
тела ролика от клиента: он забирает файл сам по `video_url`, и адрес должен
быть публично доступен (`tools/instagram_publish.py`). Единственный
публичный адрес, которым проект управляет, — сам сайт. Выкладка при этом
зеркалит репозиторий с `--delete` (`deploy.yml`), поэтому файл, положенный
на сервер мимо репозитория, удаляется следующей выкладкой. Отсюда: ролик
живёт здесь, деплой выносит его на `https://marzhavbetone.ru/media/<имя>.mp4`.

Каталог не входит в список исключений выкладки — это проверяется списком
`EXCLUDES` в `.github/workflows/deploy.yml`, где перечислены `tools`,
`content`, `orders` и остальное невыкладываемое.

**Чем это оплачено.** Ролик весит около 6 МБ, и он остаётся в истории git
навсегда. На одном ролике это ничто, на полусотне — треть гигабайта, и
каждая выкладка гонит их заново. Порог, за которым способ надо менять,
называется числом заранее: **десять роликов**. Дойдя до него, следующая
сессия не изобретает, а берёт готовую развилку — держать файлы релизными
вложениями GitHub (публичный адрес есть, истории репозитория не касается)
либо чистить каталог после публикации, оставляя ролик только в Instagram.

**Что здесь не лежит.** Промежуточные файлы сборки — видеоряд без надписей,
немой монтаж, wav озвучки. Они собираются заново из сценария за минуту
(`tools/build_reel_full.sh`), а озвучка кэшируется рядом с выдачей.

## Обратный случай никем не ловился, и ролик 3 на нём попался

Скрипт сведения достраивает хвост, когда голос **длиннее** картинки.
Когда он **короче**, ролик доигрывает молча, и не говорит об этом ни одна
проверка: `check_reel.py` читает сценарий, а `ffprobe` показывает общую
длительность файла, совпадающую со сценарием.

Замер 16.08.2026: у ролика 3 дорожка кончалась на 18,7 с при видео 22,0 с
— последние 3,3 секунды шли без звука, ровно на финальном кадре. Нашлось
это не проверкой, а тем, что владелец включил ролик.

Как ловить: сравнивать длительность **потоков**, а не файла.

```bash
ffprobe -v error -select_streams a:0 -show_entries stream=duration -of csv=p=0 media/<файл>.mp4
ffprobe -v error -select_streams v:0 -show_entries stream=duration -of csv=p=0 media/<файл>.mp4
```

Ролик 3 обрезан по концу дорожки решением владельца 16.08.2026. Цена
решения названа прямо: кадр «Проверьте эту строку до первого КС» стоял в
сценарии на 20–22 с и в обрезанную версию не попал. Голос эту фразу
произносит — она последняя в озвучке, — но на экране её больше нет, и
ролик заканчивается на «Подпись не решает, когда заплатят».

## Как публикуется

Кнопкой владельца, не сессией: прогон `instagram.yml`, режим `publish`,
`media_url` — адрес файла отсюда на боевом сайте, `caption_file` —
`content/reels/captions/<имя>.txt`. Публикация необратима и направлена
наружу, поэтому нажатие остаётся за владельцем (Р-006).

Разовая настройка доступа — `docs/INSTAGRAM_SETUP.md`. Этот каталог
закрывает второе условие публикации: `media_url` из той инструкции неоткуда
взять, пока файла нет на боевом сайте.

## Как пересобрать

```bash
apt-get install -y ffmpeg   # в свежей сессии его нет
AI_BUSINESS_OS=../ai-business-os \
  tools/build_reel_full.sh 01-uderzhanie 01-uderzhanie-5-millionov media/
```

Первый аргумент — имя планов и озвучки, второй — имя сценария, третий —
куда положить. Озвучка кэшируется в `<каталог>/voice/`; этот кэш в
репозиторий не кладётся, поэтому пересборка в чистой сессии заново платит
за синтез. Именно поэтому готовый mp4 здесь и лежит: спринт 16.08.2026
собрал три ролика и не сохранил ни одного, и следующая сборка оплатила бы
то же самое повторно.
