## 4. Почему STOP, а не «написать и отдать на сверку»

- Договор подписывают со второй стороной. Ошибка в формулировке цены, срока
  или приёмки работает против покупателя. Это та же цена ошибки, из-за
  которой #293 §7 п.10 поставил на R2-P7 «плюс юридическая приёмка».
- Четыре раздела из семнадцати (предмет, цена, сроки, подсудность) стоят на
  нормах, которые в репозитории не сверялись ни разу. Удержание нормой не
  регулируется, и формулировки под него нет. Писать эти пункты — значит
  выдумывать существенные условия и делать непроверенные юридические
  заявления. Задача это прямо запрещает.
- Где нормы подтверждены (приёмка, оплата, зачёт, отказ, приостановка,
  уведомления), нет утверждённого текста пункта. Сверка подтверждала нормы
  под письма и памятки, а не под договорные условия.
- Единственный образец протокола (§3.3) не сверен и содержит известный
  дефект.

## 7. Спецификация реализации (когда STOP снят)

Область — только P7.

**Генератор.** `products-storage/build_paid_03.py`: номер по каталогу, как у
`build_paid_02/05/06.py`. Пишет `00-INSTRUKCIYA.docx/.pdf`, `01`, `04`,
`06`, `07`, `10` и `00-START-HERE.txt`. Повторный прогон даёт тот же текст:
тест сравнивает извлечённый текст, а не байты zip. PDF — через
`soffice --headless --convert-to pdf`. `02`, `03`, `05`, `08`, `09` меняются,
только если на них ссылается новый текст.

**Содержание.**
- `01` — сквозной договор: разделы §3.1 с нумерацией пунктов; приложения
  `02`–`05` названы в тексте по номерам. Числовых значений нет: поля
  `{{…}}` или `[___]` с подсказкой, откуда брать. Колонтитулов продавца нет
  (P7-02, X-06).
- `10` — преамбула, таблица «№ / пункт договора / редакция генподрядчика /
  редакция субподрядчика / обоснование», строки с формулировками замены по
  подтверждённым нормам, «в остальном стороны руководствуются договором»,
  подписи. Отметку подавать как рекомендуемую практику, без автоматизма (Н-1).
- `00-INSTRUKCIYA` — текущее имя из `products-config.php`, два случая из
  START-HERE §2 («прислали свой договор» → 09 → 08 → 10; «предлагаете свой» →
  01 + 02–05), все 13 файлов. Либо инструкция удаляется, и START-HERE §2
  называет первым `08-krasnye-flagi.pdf` (A26 из #300).

**Тесты** (`tools/test_p7_contract_kit.py`, pytest):
1. В `01` нет строки «твёрдая / приблизительная / по единичным расценкам»,
   объём не меньше порога, который задаёт утверждённый текст. Разделы §3.1
   присутствуют заголовками, приложения 1–4 названы.
2. В `10` таблица позиций больше чем с одной строкой данных, есть преамбула с
   полями сторон, блок подписей, и нет фразы «считается подписанным в
   редакции».
3. Два случая START-HERE §2 названы в `00-INSTRUKCIYA`. Имя в инструкции
   совпадает с `products-config.php['p7']['name']`, старого «Договор подряда»
   нет.
4. Список файлов START-HERE §4 = состав архива `mvb_build_product_zip('p7')`
   = «файлов в архиве: N».
5. В колонтитулах `01`, `04`, `06`, `07`, `10` нет «МАРЖА В БЕТОНЕ», «РАБОЧИЙ
   ШАБЛОН», «marzhavbetone.ru».

**Приёмка.** Writer открывает все .docx (конвертация в PDF без ошибок), рендер
`01` и `10` просмотрен глазами. Calc пересчитывает `02`, `03`, `05` без `Err:`.
Архив собирается через `mvb_build_product_zip`, число файлов совпадает со
START-HERE. Р-026 — отдельным заходом `normative-checker` до выдачи. Вычитка
юристом — по решению владельца (A17 из #300).
