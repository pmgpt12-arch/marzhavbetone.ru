# P3 — устранение выявленных покупательской приёмкой ложноположительных статусов

Основа — PR #649, точный HEAD `96f924dc5205590f96fec67dfb6a53cf9844be82`. Отрицательные сценарии выполнены отдельно от автора архива на Microsoft Excel 2016, по производной QA-копии с неизменными формулами.

## Выявленная первопричина

- XLSX №06: пробелы в идентификаторе или доказательстве вручения приводили к «ЗАКРЫТО»; произвольная несуществующая ссылка O6 на предыдущую передачу не блокировала строку. Нативный отчёт `p3-649-independent-negative-buyer-20261015-v1`: FAIL, SHA256 `bc02cddeed2829993e00b1003eb488cd076d77924780c09603070582ae72843b`.
- XLSX №02: отсутствие TRIM-контроля в номере документа C и основании неприменимости G позволяло подставить пробелы.

**Класс:** WHITE_SPACE_FALSE_READY / UNVERIFIED_PREVIOUS_DELIVERY_LINK. Постоянный gate: 50/50 формул каждой книги должны отвергать пробелы в обязательных текстовых полях; при повторной передаче номер предыдущей строки A должен существовать выше и соответствовать КС-2/КС-3. Отрицательные проверки встроены в `verify_buyer_fixes.py`.
