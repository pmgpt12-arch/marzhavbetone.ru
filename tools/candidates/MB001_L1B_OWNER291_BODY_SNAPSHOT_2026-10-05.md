## Обязательный preflight исполнения — решение владельца 02.10.2026
Перед каждым новым запуском оценить всю достижимую цель, а не только ближайший Issue, и составить краткую исполнимую цепочку: objective → атомарные задачи → зависимости → параллельные ветки → исполнитель → артефакт → проверка → следующий шаг.

Декомпозировать крупную работу на минимальные независимые единицы. Запускать одновременно максимальное число задач, у которых нет пересечения по файлам, общему состоянию, лимиту ресурса или обязательной зависимости. Для каждой ветки выбирать наименьший достаточный инструмент: Python/CLI/серверные средства для детерминированных извлечений, сборок, хешей, формул и тестов; бесплатную модель только для ограниченного вспомогательного результата с детерминированной проверкой; сильный exact API для продуктовых решений, права, финансовой логики, сложного кода и независимой приёмки. Результаты веток хранить раздельно и сводить только через явный gate.

Preflight перед запуском: TASK VALIDITY → ATOMICITY → CONTEXT → CONTRACT → DEPENDENCIES → TOOLS/PERMISSIONS → CONCURRENCY/CAPACITY. Если общий план или контракт неполны, сначала исправить постановку. Параллельность не отменяет quality gates, отдельного проверяющего и запрета blind retry. После каждого завершения пересчитать следующую волну по фактическим артефактам, а не по памяти.
