## Фактический маршрут

Синтетический paid-заказ с явным точным edition-marker → существующие функции блокировки/записи заказа, подготовки выдачи и уведомления через CLI-fixture → сохранённый JSON заказа и локально перехваченное уведомление → выданная ссылка → настоящий HTTP GET к неизменённой принятой временной копии download.php.

Слушатель: PHP CLI development server, bind только `127.0.0.1`, случайный свободный порт. Публичный адрес не создавался. В HTTP document root находятся только временные runtime-копии; заказы, архивы, письмо и CLI-fixture — вне него. HTTP-тест не использует новый router. Нативная PHP mail отключена при старте; локальный перехватчик допускает только адреса `@fixture.invalid`. Запросы HTTP не используют proxy или внешние узлы.

## Проверено

- Новый P11: HTTP 200, точные 592882 байта и SHA принятого ZIP; корректные Content-Type, Content-Length, Content-Disposition и nosniff. Счётчик сохраняется 0→1, повторное скачивание 1→2.
- После HTTP-скачивания повтор уведомления сохраняет заказ, токен, издание и счётчик; захвачено ровно одно уведомление. Принятый текст письма включён дословно, отдельно от архива.
- Неверный токен/неоплата: 403; чужая позиция: 404; истёкшая ссылка: 410; исчерпанный лимит: 429; отсутствующие метаданные издания, повреждённый или отсутствующий снимок: 500. Отказ не расходует скачивание и не подменяет архив.
- Прежние синтетические P11/T6: HTTP 200 и первоначальные байты до и после нового unmarked-заказа при более новых masters. Сохранены токены; счётчик каждого старого заказа меняется только от успешного HTTP-скачивания. Отсутствующий исторический снимок не пересобирается.
- Служебный JSON тестового заказа недоступен из временного HTTP document root. Это свойство стенда, не проверка конфигурации production.
- Входы и временные runtime-копии не изменены тестом; PHP fatal/warning/notice не обнаружены; дочерний HTTP-процесс остановлен; временный каталог удалён.

42 — число проверок, включая SHA/preflight/cleanup. 17 — число реальных HTTP-запросов. Не называть их 42 независимыми покупательскими сценариями.

## Воспроизведение независимым проверяющим

Нужны Python 3, PHP с ZIP, доступные локально immutable Git-объекты указанных SHA и разрешённое соединение с 127.0.0.1. Пример одной команды из корня подготовленного репозитория:

`python3 tools/candidates/p11-http-transport-20261014/test_http_transport.py --repo . --output /tmp/p11-http-independent-result.json`

Тест не fetch/checkout/merge и не меняет отслеживаемые файлы. При отсутствии точного объекта — STOP, без догадок о версии. Бюджет самого теста 60 секунд, запуск HTTP ≤3 секунд, HTTP-запрос ≤3 секунд, PHP CLI ≤5 секунд. Один процесс запускается один раз; readiness polling не перезапускает его. Любая ошибка даёт FAIL и сохранённое объяснение; cleanup выполняется в finally.

Локально до запуска проверены Python compile и PHP lint двух служебных текстов. Первоначальная составная удалённая диагностика была заблокирована до исполнения; она не считалась результатом. Локальный контейнер не имел ZIP-модуля PHP и DNS-доступа к raw GitHub; тест там не запускался, установки/повторы сетевого обращения не делались. Узкая read-only проверка сервера затем подтвердила PHP 8.3.6 + ZIP. Фактический HTTP-прогон выполнен один раз на сервере с точными GitHub-входами.
