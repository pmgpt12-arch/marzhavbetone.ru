# Предложение: событие фактической серверной выдачи оплаченного ZIP

Статус: подготовлено и проверено в изолированной копии, **не применено** к рабочему `download.php`. Требует разрешения владельца на узкое изменение защищённого endpoint-а. Merge/deploy не разрешены.

## Изменение

`download-served.patch` заменяет единственный завершающий `readfile()` на проверку числа выданных байтов. После полного GET и при отсутствии обнаруженного разрыва соединения используется существующий сборщик `mvb_funnel.php`.

Событие — существующее канонное `funnel.product_delivered` с `sku` и `source=site`. Новое неподдерживаемое имя `funnel.download_served` не вводится. HEAD, отказы доступа и неуспешный `readfile()` не создают событие. Существующие правила доступа, цена, срок ссылки, счётчик и сборка ZIP не меняются.

Повторный GET того же SKU в заказе не создаёт новую строку после успешной записи флага `delivery.served_events[sku]`. Проверка и запись происходят под существующей блокировкой заказа. При отказе сборщика флаг не ставится; следующий полный GET может повторить запись. UUID детерминирован по заказу/SKU, открытый ID заказа, токен, почта и телефон в событие не включаются.

## Фактическая проверка

`PROPOSAL_ACCEPTANCE.json` фиксирует три запуска настоящего PHP с cURL/ZIP на ai-workstation. Использованы локальный mock API и синтетический заказ; mail отключён. Каждый запуск проверяет payment → повторный webhook → тело письма → HTTP ZIP и SHA всех 11 файлов текущего P3.

- Исправный сборщик: HEAD/неверный токен/чужой SKU дают ноль событий; три полных GET дают одну строку события.
- Недоступный сборщик: первый GET всё равно отдаёт точный ZIP, флаг отсутствует. После восстановления следующий GET записывает событие, следующий повтор не дублирует его.
- Отсутствующий файл сборщика: все GET отдают точный ZIP, событий нет; аналитика не ломает выдачу.

Патч прошёл `git apply --check` против исходного `download.php`; PHP lint пройден. Хеш исходника и кандидата сохранён в подтверждении. Оригинальный endpoint в ветке побайтово совпадает с базой c7e32ec.

## Границы доказательства

Событие подтверждает полную выдачу байтов сервером, а не сохранение файла устройством покупателя. Проверены локальная очередь и штатные повторные запросы. При аварии между записью события и сохранением флага возможна повторная строка с тем же UUID; окончательная дедупликация и приём канонного события потребителем требуют отдельной проверки. Реальные провайдер, почтовая доставка, обработчик очереди и продакшен не затрагивались. Атрибуция к anonymous_id/session_id не добавляется.

Для воспроизведения создать изолированную копию текущих payment.php/products-config.php/webhook.php/download.php/mvb_funnel.php и products-storage/05-ks-bez-vozvrata. Проверить патч, применить его только в этой копии, затем выполнить три раза:

```bash
NSP_PROPOSAL_ROOT=/absolute/isolated/copy NSP_PROPOSAL_MODE=healthy python3 test_download_proposal.py
NSP_PROPOSAL_ROOT=/absolute/isolated/copy NSP_PROPOSAL_MODE=failure_recovery python3 test_download_proposal.py
NSP_PROPOSAL_ROOT=/absolute/isolated/copy NSP_PROPOSAL_MODE=missing_library python3 test_download_proposal.py
```

Нужен нативный PHP с cURL и ZIP. Результат не заменяет тестовый платёж и доставку письма из отдельного тестового магазина.
