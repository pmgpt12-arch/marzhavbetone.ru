## Подготовленный патч серверного события выдачи

В proposal/ находятся точный download-served.patch, кандидат, воспроизводимый тест и PROPOSAL_ACCEPTANCE.json. Патч **не применён** к рабочему download.php: прежний запрет владельца на изменение endpoint-ов сохраняется.

Три сценария проверены на нативном PHP в изолированной копии: исправная очередь, отказ с восстановлением, отсутствующая библиотека аналитики. Повторные GET не дублируют штатное событие; HEAD/отказы доступа не создают события; отказ аналитики не мешает ZIP. Во всех сценариях SHA 11/11 файлов совпал с текущими мастерами P3. API только локальный mock, отправка почты отключена.

Используется существующее канонное funnel.product_delivered, обязательный sku подтверждён в исходнике потребителя. Нового неподдерживаемого типа download_served нет. Границы — в proposal/README.md: серверная выдача не доказывает сохранение на устройстве, аварийная дедупликация у потребителя и живая обработка очереди ещё не проверены.

## Открыто для окончательной приёмки

1. Настоящая транзакция отдельного тестового магазина и доставка письма.
2. Разрешение на узкий патч защищённого download.php, затем отдельная проверка потребителя события. Бесплатная серверная выдача этим патчем не покрыта.
3. Поступление событий с опубликованным кандидатом — только после отдельного разрешения на выпуск. Нынешние доказательства разрешением на выпуск не являются.

## Правило сохранности доказательств

Исторический отчёт проверяет собственный неизменный Git-источник. Текущая область допускается только через фиксированный ref, точное сравнение исходников и негативные мутации. Произвольный HEAD не становится эталоном. Транспортные bundle проверяются по формату, точному размеру и SHA-256 до git fetch/push: exit=0 чтения не исключает усечения stdout.
