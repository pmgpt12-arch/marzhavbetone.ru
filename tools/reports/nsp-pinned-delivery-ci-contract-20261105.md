## Наблюдаемое
Действующий PHP теперь проверяет заранее закреплённые ZIP по SHA-256 для **11 платных SKU** (P1, P2, P3, P4, P5, P7, P8, P9, P10, P11, P13). По дереву PR #692 в публичном `products-storage/` таких ZIP **0**; хранилище production в этом инкременте не обследовалось.

В [CI #42063489397](https://github.com/pmgpt12-arch/marzhavbetone.ru/actions/runs/42063489397) четыре проверки, проходившие на старом коде в [#42039761544](https://github.com/pmgpt12-arch/marzhavbetone.ru/actions/runs/42039761544), теперь FAIL:
1. `test_p1_immutable_edition` — ожидает создание нового издания из распакованных файлов; получает HTTP 503 без master P1 ZIP.
2. `test_p1_price_http` — проверяет прежний R3-архив, а новый код требует другой закреплённый P1 SHA; получает HTTP 503.
3. `test_delivery_cache_freshness` — берёт первый SKU P1, но обновление по mtime больше не применяется к pinned SKU; тест не собирает архив.
4. `verify_delivery_zips` — сравнивает все архивы с каталогами распакованных мастеров; 11 новых pinned SKU не доступны в этом режиме.

Профильные почтовые тесты PASS. Старые красные проверки сайта/каталога существуют отдельно. **Эти CI-ошибки нельзя объявлять производственными сбоями без теста на реальном хостинге; также нельзя считать весь продуктовый QA пройденным.**
