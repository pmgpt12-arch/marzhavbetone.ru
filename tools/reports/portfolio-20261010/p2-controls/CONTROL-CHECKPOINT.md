## Системная ошибка и gate

Ошибка: zero input смешивался с empty string; preview при нулевом количестве возвращал пусто, native fixture при нулевом коэффициенте400 вместо0. Результат первой Calc-конверсии нельзя переносить на позднее пересозданный fixture; старые файлы/FAIL сохранены для диагностики, новый прогон имеет другой каталог и SHA.

Правило: у пользовательских числовых полей проверять фактически пустую ячейку отдельно от0; не принимать сохранённый cache/предпросмотр за пересчёт. Gate: отдельные positive/zero_quantity/zero_coefficient/blank_coefficient/blank_quantity/negative/text сценарии; точный input/outputSHA и output не старше input. `verify_native.py` делает проверку и прекращает работу при несовпадении; blank v правильно читается как пустая строка, не None.

В authoring-движке прошли7 случаев, включая строку103 и итог104. В LibreOfficeDev26.8.0.0.alpha0 прошли7 сценариев с ожидаемым #VALUE! при тексте. Сохранены fixture, output и results. Это проверка арифметики в совместимом движке, не MicrosoftExcel и не полная G3/G4. Все изменённые виды и неверный числовой ввод просмотрены; неизменённая инструкция не перерабатывалась.

## Ограничения инструмента и первопричины

В public API отсутствует документированная защита листа: два ограниченных запроса справки не нашли операции. Отсутствие печатного API установлено ранее; дополнительные поиски не повторялись. Защита/formula unlocking и pageSetup/printareas/titles остаются атомарной задачей существующего серверного контура; неподдерживаемые поля и обходное OOXML authoring не применялись.

Ошибка API `allowBlank` — SCHEMA/TOOLS: справка показывает параметр, runtime отвергает. Удалён только этот необязательный параметр; поведение очистки статуса требует native UI проверки. Это не MODEL_CAPABILITY. Каждый entrypoint ограничивает ошибку через catch(message), чтобы stack dump минифицированной библиотеки не переполнял контекст. Не запускать новую попытку без исправления конкретной причины.
